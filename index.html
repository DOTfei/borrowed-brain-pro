DECISION WORKFLOW

From dilemma to reviewable contract.

Every decision follows the same evidence-first path. The output is a record you can return to, not a personality performance.

01

Evidence Boundary

Separates observed facts, reported claims, AI inferences, and unknowns before a recommendation is made.

"Unknown: What makes users stay?"
02

Lens Comparison

Applies different decision lenses and names their shared recommendation, disagreement, and missing perspective.

"Conflict: Simplify first vs. validate first"
03

Failure Boundary

Compares the decision with documented post-mortems and states both the useful parallel and the important difference.

"Analogy, not prediction"
CORE VALUE
04

Test + Review

Commits the lowest-cost test, target signal, threshold, owner, due date, and review date before action begins.

"Prediction → Signal → Review"
WORKED EXAMPLE · ILLUSTRATIVE

A decision record, not a personality simulation.

This worked example shows the protocol on a builder dilemma. It is illustrative: no user outcome or product telemetry is being claimed.

Jobs @ NeXT Munger @ Alibaba Hastings @ Qwikster Musk @ Model 3
Dilemma: "Automate the entire customer onboarding pipeline before manually learning which steps matter."
STEP 1 — EVIDENCE BOUNDARY
Unknown "You have not observed 10 users completing the flow manually, so the necessary steps are still a hypothesis."
STEP 2 — LENS DISAGREEMENT
Process Simplification "Delete unnecessary steps before automating them."
STEP 3 — FAILURE BOUNDARY
Model 3 Case "Automation increased complexity in a workflow that had not been simplified first. The analogy has limits."
STEP 4 — TEST + REVIEW
Manually onboard the next 5 users, record hesitation and completion, then review the automation decision against that signal.
